# Проверка и диагностика

1. Убедись, что прокси запущен и клиент использует его адрес; для VPS проверь корректность HTTPS-сертификата. Не публикуй вывод с ключами или заголовками авторизации.
2. Открой список моделей через настроенный клиент и выбери модель, доступную твоему аккаунту. Список моделей сам по себе не доказывает успешную генерацию.
3. Отправь короткий запрос и проверь ответ. По журналу или статистике прокси без вывода содержимого секретов убедись, что запрос прошёл именно через него. Ответ без такой проверки не исключает прямое подключение.
4. При необходимости проверь маршрут с отключённым VPN, если это соответствует условиям провайдера. VPN может оставаться нужен для отдельных сайтов и входа в аккаунт.

## Проверка ошибочным адресом

Этот тест помогает обнаружить прямое подключение в обход настройки. Сохрани текущий адрес и выполняй проверку в отдельной сессии без чувствительных запросов:

1. В Pi временно поставь в `/cliproxyapi config` адрес `https://proxy.invalid/v1`, в Codex — `base_url = "https://proxy.invalid/v1"`, в Claude Code — `ANTHROPIC_BASE_URL=https://proxy.invalid`. Перезапусти соответствующий клиент.
2. Отправь короткий запрос. Ожидается ошибка соединения. Если ответ пришёл, проверь выбранного провайдера и приоритет настроек: клиент мог подключиться напрямую или использовать другую конфигурацию.
3. Восстанови прежний адрес, перезапусти клиент и повтори запрос. Не оставляй ошибочный адрес в настройках.

Дополнительно можно сравнить статистику или журнал прокси до и после запроса. На общем прокси чужие запросы могут исказить результат; не сохраняй содержимое запросов или ключи в отчёт. Расположение статистики зависит от версии приложения, поэтому проверяй документацию установленной версии.

| Симптом | Что проверить |
|---|---|
| Нет соединения | Адрес, DNS, HTTPS, состояние сервиса и сети. |
| Ошибка авторизации | Используется клиентский ключ прокси; переменная доступна процессу; ключ управления не подставлен вместо клиентского. |
| Нет моделей | Состояние авторизации подписки, `/v1` в адресе Pi и Codex, настройки клиента и совместимость версий. |
| Запрос отклонён провайдером | Доступность модели, лимит подписки, регион и условия провайдера. Не считай обход ошибки гарантированным. |
| Клиент идёт напрямую | Текущий провайдер и приоритет настроек; перезапуск клиента после изменения окружения. |

Для отката верни прежние настройки клиента и переменные среды. При утечке ключа отзови его в панели и создай новый; при утечке OAuth-токена заверши сессии у провайдера.
